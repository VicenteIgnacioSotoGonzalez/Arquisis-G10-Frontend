# E3-032 a E3-034 — Cliente SSE y reanudación

`src/services/sse.js` incorpora un cliente separado de `apiFetch()` para consumir `GET /events/stream` con un access token de Auth0. La opción **Actividad en vivo** de la pantalla principal abre el panel E3-052.

## Ejemplo de uso desde un componente React

```jsx
import { useEffect } from 'react'
import { openSseFeed } from '../services/sse.js'

export default function FeedObserver({ enabled }) {
  useEffect(() => {
    if (!enabled) return
    const connection = openSseFeed({
      onEvent: (event) => console.info('SSE', event.type, event.id),
      onStatus: (status) => console.info('SSE status', status),
      onError: () => console.warn('SSE connection unavailable'),
    })
    return () => connection.close()
  }, [enabled])
  return null
}
```

El panel enlaza el servicio SSE con la cuenta activa de Auth0 mientras está montado. Salir del panel, cerrar sesión o cambiar de cuenta aborta la conexión anterior y descarta la lista visible. Volver a abrirlo recupera el cursor guardado para esa cuenta y autorización. El panel conserva en memoria los últimos 100 eventos de la vista, por ID de publicación descendente, y muestra la hora de captura en la zona local del navegador.

El cliente abre un `fetch` con Bearer, interpreta UTF-8 de forma incremental y descarta tramas incompletas, inválidas y duplicadas. Avanza el cursor cuando termina `onEvent`, incluso si el callback devuelve una promesa. Usa `Last-Event-ID` y backoff para reconectar después de un corte. Los comentarios del stream mantienen la conexión y no avanzan el cursor.

En `localStorage` se guarda únicamente el ID público precedido por una clave derivada de la API, emisor, sujeto, audiencia y permisos. La misma cuenta con la misma autorización puede recuperar su cursor al entrar de nuevo. Los tokens y los eventos quedan fuera del almacenamiento SSE. Si el navegador bloquea almacenamiento o criptografía, la conexión conserva el cursor en memoria.

Ante un `401`, la sesión Auth0 puede solicitar un token fresco una vez. Un `403` detiene la conexión y descarta su cursor. Un `400` o `409` elimina el cursor y emite `invalid-cursor`. La vista debe limpiar su historial visible antes de abrir deliberadamente una conexión desde el comienzo. Un `503` usa el backoff y conserva el último cursor procesado.

## Pruebas

En la raíz del frontend, ejecutar los scripts con Node.js 22:

```bash
npm test
npm run lint
npm run build
```

**Limitaciones de despliegue:** deben estar disponibles la ruta SSE pública en la API y streaming HTTP real en API Gateway. `npm test` no sustituye la prueba de extremo a extremo.
