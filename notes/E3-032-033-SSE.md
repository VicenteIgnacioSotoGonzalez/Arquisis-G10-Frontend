# E3-032/E3-033 — Cliente preparado para SSE

`src/services/sse.js` incorpora un cliente separado de `apiFetch()` para consumir el stream `GET /events/stream` usando el access token que entrega `src/services/auth.js` tras Auth0. No incluye un dashboard nuevo (E3-052–054).

## Ejemplo de uso desde un componente React

```jsx
import { useEffect } from 'react'
import { openSseFeed } from '../services/sse.js'

export default function FeedObserver({ enabled = true }) {
  useEffect(() => {
    if (!enabled) return
    const connection = openSseFeed({
      onEvent: (event) => console.info('SSE', event.type, event.id),
      onStatus: (status) => console.info('SSE status', status),
      onError: () => console.warn('SSE connection unavailable'),
    })
    return () => connection.close()
  }, [enabled])
  return null
}
```

El ejemplo no debe integrarse directamente al dashboard de producción sin gestionar un estado visual y el ciclo de autenticación; se incluye para probar el cliente manualmente en E3-052.

El cliente: conecta con Authorization Bearer en el header; procesa chunks UTF-8 de forma incremental; ignora keepalives, duplicados y eventos no reconocidos; guarda en memoria el último ID procesado; reintenta con backoff y aborta durante el desmontaje. No usa `EventSource` con JWT en URL, `sessionStorage`, ni polling HTTP.

No expone tokens mediante URL ni logs. Los eventos no se usan para ejecutar pagos ni swaps, sólo observación.

## Pruebas

Tras descomprimir el ZIP en la raíz del frontend, ejecutar:

```bash
npm test
npm run lint
npm run build
```

**Limitaciones de despliegue:** deben estar disponibles la ruta SSE pública en la API y streaming HTTP real en API Gateway. `npm test` no sustituye la prueba de extremo a extremo.
